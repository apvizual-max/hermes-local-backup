## 2026-08-05 — A2A Toolset Warning Investigation (Mode A)

### Problem
User runs `hermes` from terminal and observes:
```
Warning: Unknown toolsets: a2a — this is an error, in read...but hermes opens and here we are taking.
```

### Root Cause (Confirmed)
1. **Config state**: `config.yaml` has `platform_toolsets.cli` containing `"a2a"` and `known_plugin_toolsets: {cli: [a2a, spotify]}`.
2. **Timing**: `_get_platform_tools(CLI_CONFIG, "cli")` calls `discover_plugins()` internally, which successfully registers the `a2a` toolset (5 client tools). However, the A2A **platform adapter** fails to load due to:
   ```
   ModuleNotFoundError: No module named 'gateway.config'; 'gateway' is not a package
   ```
3. **Validation gap**: `HermesCLI.__init__` (cli.py:4466) validates toolsets via `validate_toolset()` **after** `_get_platform_tools` runs. In some execution paths, `discover_plugins()` has not completed (or its results are not visible) when the validation runs, so `validate_toolset("a2a")` returns `False` → triggers the warning.
4. The A2A adapter import chain: `adapter.py:49 → gateway.platforms.base → hermes_cli/gateway.py:32 → gateway.config` — this is a module shadowing conflict where `hermes_cli/gateway.py` (module) shadows the `gateway/` package.

### Findings
- `validate_toolset("a2a")` returns `False` when called **before** `discover_plugins()` has run.
- `validate_toolset("a2a")` returns `True` when called **after** `discover_plugins()` has run (because `_get_plugin_toolset_names()` returns `{"a2a"}`).
- The A2A plugin's client tools (outbound) are registered successfully; only the inbound platform adapter fails.
- `known_plugin_toolsets.cli` = `['a2a', 'spotify']` — these are explicitly user-selected, so they should not trigger "unknown" warnings.

### Remediation Plan (awaiting R0)
1. **Fix gateway.config import** (root cause) — resolve module shadowing conflict in `hermes_cli/gateway.py`.
2. **Fix toolset validation** (symptom) — in `cli.py:4466`, skip validation for toolset names present in `known_plugin_toolsets[platform]`.
3. **Guarded A2A adapter import** — wrap `from .adapter import A2AAdapter` in try/except in `a2a/__init__.py` (already done, but the inner import error should be handled).

## 2026-08-05 — A2A Toolset Warning Fix (Mode B)

### Problem
Running `hermes` from terminal showed: `Warning: Unknown toolsets: a2a`

### Root Cause (3 layers)
1. **Validation timing**: `HermesCLI.__init__` (cli.py:4466) validates toolsets via `validate_toolset("a2a")` BEFORE plugin discovery has registered the A2A toolset. Platform plugins are loaded deferred, so their client tools are invisible.
2. **Module shadowing**: `hermes_cli/gateway.py` (module) shadows `gateway/` (package), causing `ModuleNotFoundError: No module named 'gateway.config'; 'gateway' is not a package` when the A2A adapter imports `gateway.platforms.base`.
3. **Deferred loading**: Bundled platform plugins (including a2a-platform) are registered deferred — their `register()` (which creates the `a2a` toolset) is never called at CLI startup.

### Fixes Applied (R0 Approved)

#### Fix 1: `cli.py` (line 4461-4468) — Warning suppression
Added `known_plugin_toolsets` exclusion to the validation check:
```python
known_plugin = set()
kpts = (CLI_CONFIG.get("known_plugin_toolsets") or {})
known_plugin.update(kpts.get("cli", []) or [])
invalid = [
    t for t in toolsets
    if not validate_toolset(t)
    and t not in mcp_names
    and t not in known_plugin
]
```

#### Fix 2: `hermes_cli/gateway.py` (line 30) — Module shadowing fix
Inserted `PROJECT_ROOT` into `sys.path` before gateway package imports:
```python
PROJECT_ROOT = Path(__file__).parent.parent.resolve()
if str(PROJECT_ROOT) not in sys.path:
    sys.path.insert(0, str(PROJECT_ROOT))
from gateway.config import ...
```

#### Fix 3: `hermes_cli/tools_config.py` (line 269) — Eager platform plugin loading
Modified `_get_plugin_toolset_keys()` to eagerly load deferred platform plugins whose toolset name matches the user's `platform_toolsets` or `known_plugin_toolsets` config entries.
